# Requirements and acceptance criteria

- **REQ-01 Editing:** Continuous raster strokes paint walls, erase, or terrain without gaps. Walls/terrain never overwrite markers. Dragging a marker changes only its final destination, clears destination obstacles, and does not erase its trail. Endpoints stay distinct. Keyboard arrows/Enter and tool shortcuts work. Edits invalidate search and comparison results.
- **REQ-02 Search:** BFS minimizes moves; heap-based Dijkstra and A* minimize cost. Four-way movement, no diagonals/row wrapping. A* uses a consistent Manhattan lower bound, with h then discovery-order tie-breaking. Return explicit unreachable results and actual route cost. Validate dimensions 1–200, cell indexes, walls, algorithms, and integer costs 1–9. The UI remains 48 × 28.
- **REQ-03 Playback:** Show frontier, visited cells, and traced paths incrementally. Play/pause/resume/step and live speed changes work. Clearing cancels animation. Pending drawing gestures finish before search snapshots. Search/comparison prevents board mutation; paused searches allow inspection.
- **REQ-04 Metrics:** Display explored/walkable counts, coverage, moves, route cost, search CPU, canvas CPU, active playback, overhead, and peak frontier entries. Pause time is excluded. Explain pacing/timer/GPU limits and make no fabricated or byte-accurate memory claim.
- **REQ-05 Recovery:** Clear path preserves the board. Clear board removes walls/terrain and restores markers. Missing routes unlock controls. Random layouts may be unreachable and say so. Valid local saves restore the board after reload; visualization restarts idle.
- **REQ-06 Usability:** Responsive controls and metrics, accessible labels/pressed states, visible focus, shape-distinct markers, keyboard canvas controls, polite results, and modal help. Target current browsers with Canvas, Pointer Events, ResizeObserver, TextEncoder, and dialog; actual tested coverage is separate evidence.
- **REQ-07 Privacy/deployment:** No added dependencies, third-party assets, application API calls, telemetry, or credentials. Browser-local storage and user-triggered JSON downloads/imports only. Local HTTP preview; direct-file startup remains unverified because preview policy blocks file URLs. Public GitHub source publication is authorized as of 2026-11-06; app hosting is outside this increment.
- **REQ-08 Saved maps:** Auto-save after completed edits, presets, maze generation, and imports, with dirty-state pagehide flush. Store only the board using pathlab.board.v1. Storage failure must show an export fallback; malformed saved data must not crash or be silently overwritten on startup. Strict version-1 JSON import validates before replacing the current board/save: exact dimensions, distinct endpoints, bounded indexes, no duplicates/overlaps, only costs 3/5/9, required arrays, no unknown fields, and at most 256 KiB UTF-8. Failed imports preserve the current board. Export round-trips through this schema. File reads cannot apply stale content after a newer selection.
- **REQ-09 Terrain:** Sand=3, mud=5, water=9; unspecified cells=1. Cost is paid on entry, excluding start. UI markers occupy unit-cost cells; erase clears both obstacles and terrain, and new terrain replaces a wall. Explain that BFS can be more expensive. Include an example demonstrating this.
- **REQ-10 Comparison:** Snapshot one board. Warm each algorithm once, then collect five runs each in rotating order. Report median search time, moves, total cost, explored count, and peak frontier entries, including no-route states. Exclude animation; include setup and event generation. Lock edits until finished and invalidate results after board changes. Timings are approximate local measurements.
- **REQ-11 Mazes:** Generate an iterative randomized backtracking maze with connected endpoints. Complexity 1–3 controls added connections (lower complexity opens more); it does not guarantee a solving difficulty. Repeated generation produces a new board and saves it. Validate supported maze dimensions 5–200 and complexity.
- **REQ-12 Inspector:** Inspect through the tool or a paused search click/Enter. Show entry cost, current search g/h/f, parent coordinates, and state. A*/Dijkstra g is cost, BFS g is moves, h is unused outside A*, and unseen values are absent. Explain the selection/tie-breaking rule. Inspection never changes the board.

Performance design: cap the search loop near 8 ms per playback frame and background catch-up. This is a loop budget, not a guaranteed frame time. Browser scheduling, drawing, and DOM work remain variable.
